CLUE CIRCUIT · FEATURE RELEASE

More moods, clearer turns.

Published release notes · October 3, 2026

A broader vocabulary, a dressed-up ghost, and clearer table management for screen-shared game nights. Clue Circuit remains a static browser game with no accounts, backend, or live multiplayer service.

Eight feature changes

1. Seven holiday moods

Diwali, Thanksgiving, Christmas, Hanukkah, Kwanzaa, Lunar New Year, and Eid join the thirteen existing moods for twenty choices. Halloween, Neon noir, Winter holiday, Arcade rush, Dungeon crawl, Space opera, Midnight noir, Heist mode, Frontier dusk, Pirate tide, Kaiju panic, Jungle pulse, and Spy thriller remain available. Switch the atmosphere without changing the rules or board.

2. A unique ghost outfit in every theme

The friendly ghost now wears an original SVG costume or accessory for each of the twenty themes, including all thirteen existing moods as well as the seven new holidays. Theme changes replace the accessory rather than accumulating decorations. The artwork is part of the app, not a remote image service.

3. Twelve expanded word collections

The collections contain 3,344 entries in total before cross-pack deduplication. Every pack has at least 200 unique entries. Added subject areas include federal Salesforce delivery with Copado and GitHub, nature, science, arts, sports, and world celebrations. Mix packs or add custom vocabulary; shared entries are removed when building the final pool. See the full names and counts below.

4. Inline card confirmation

Selecting a card flips it to Reveal / Cancel controls in place instead of opening a reveal modal. For keyboard play, Enter opens confirmation with focus on Cancel. Another Enter cancels; Tab moves to Reveal for an intentional confirmation. Escape cancels the pending guess. The workflow keeps the decision attached to its card.

5. Explicit inline reveal results

CORRECT! and WRONG! feedback describes the reveal and what happens next without interrupting play with a modal. Correct agents may allow another guess; bystanders and opposing agents end the turn unless a win has been reached. The trap immediately loses the round. Public status messaging accompanies the visual feedback.

6. Separate clue and operator clocks

The host runs a spymaster-clue clock and an operator-turn clock, with pause/resume and editable limits. Expiry automatically passes to the other team’s spymaster, including a clue phase where no clue was submitted. Every guess in an operator turn shares one budget: correct guesses do not restart it. Paused play blocks clues and reveals.

7. Vocabulary difficulty and editable presets

Easy and Hard use curated selections in every pack; Standard uses the full selected collections. Each pack has at least 50 Easy and 50 Hard entries, and the picker displays the selected difficulty’s available count. Custom words remain unfiltered. Difficulty supplies the timer presets, which the host may override independently.

8. Dedicated per-team clue tracking

Clues by team records the spoken clue word, count, and turn number in separate team histories. This structured tracker sits alongside the broader Mission log, making it easier to revisit earlier clues without searching through reveal and turn events. It is shown on the host board, not synchronized to invitations.

Either limit accepts whole seconds from 10–1,800 in setup or the host board’s Time limits. Saving restarts the current phase’s clock, preserving a paused state. Limits are host-editable and honor-system: there is no remote referee or server enforcement.

Clocks use saved wall-clock deadlines. Returning from a background tab or opening an expired save passes the expired turn once, then starts a fresh clue phase rather than forfeiting many unseen turns. Undo restores the prior state with a fresh clock for its phase. Pause explicitly before breaks or distributing keys.

Existing saves and next rounds

  • Older saves: saves without clock settings receive Standard timers (120 seconds for each phase). Their existing board is not automatically redealt or vocabulary-filtered, and the existing mission log is retained.
  • Clue history migration: the dedicated tracker records newly entered structured clues. It does not reconstruct past clues from older mission-log text.
  • New board: preserves teams, the current pool, difficulty, and limits while replacing the round. Send fresh spymaster keys and optional operator links after every redeal.
  • Packs & difficulty: returns to setup and pauses the existing board. Resume last game restores that board; dealing from setup replaces it using the newly selected vocabulary and settings.
  • Roster edits: existing invitations keep their original names and board. After Edit teams, distribute new links; invitations do not update themselves.

Compatibility and limitations

No new dependencies are required. The interface continues using the bundled Anime.js and Motion libraries, with system reduced-motion support, a visible animation-reduction toggle, responsive layouts, and host Focus mode. The app makes no runtime CDN requests.

  • Not live multiplayer: key links and operator invitations are snapshots. There is no synchronization, presence, online membership, shared controller, or remote clock. Follow the host’s shared screen.
  • Private means handle carefully: both spymasters see the full color key. Private key marks stay local. Never screen-share a key; share only the host board tab. Anyone with a key link can read it, and old links cannot be revoked remotely.
  • Honor-system storage: the host holds the full answers in localStorage even though its ordinary board hides them. Use one host tab; clearing browser site data removes local saves and marks. Operator snapshots omit unrevealed answers.
  • Clue conventions remain human: the app checks clue format, exact unrevealed-word matches, and counts 1–9, but makes no automatic clue judgments about meaning or fairness. Zero and unlimited counts are unsupported. Guess allowance remains count + 1.
  • Hosted requests: there is no game backend or analytics. The web host still receives normal website requests; names embedded in invitations are visible to their recipients.

See the host, spymaster, operator, and spectator guides for practical before, during, and after-play instructions.

Publishing and the standalone offline app

Publish the site and documentation with GitHub Pages

  1. Keep the application assets and these HTML pages together in docs/. The guides and release notes both use ./style.css and relative links.
  2. In repository Settings → Pages, choose Deploy from a branch, then select main and /docs and save.
  3. After deployment, open https://jsc1100.github.io/clue-circuit/. The documentation is at guides.html and release-notes.html under that site. For a fork or renamed repository, use its own Pages address.

No build step or package installation is required for the Pages site. These instructions describe deployment; they do not assert that a particular deployment is already available.

Regenerate the downloadable HTML

  1. With Node.js 22 or newer, run node scripts/build-offline.mjs from the repository root after application source changes.
  2. The script writes play-offline.html at the repository root, embedding the game’s code, styles, word packs, and existing animation libraries. Open that file directly in a browser to play without a server.
  3. Distribute the regenerated file as the standalone download. Publish the docs/ site separately so documentation and hosted invitation pages are available.

Offline gameplay, online documentation: gameplay in the downloaded single HTML file does not require a network. Its in-app documentation links open the published web guides and release notes rather than embedding those documents. Reading them through those links requires network access. If you need offline documentation, save these pages and their stylesheet separately.

For local hosted play, npm start serves the site at http://localhost:3000 without an install step. This is a static server, not a multiplayer backend; remote teammates generally cannot reach your localhost. Supply a reachable public URL in Team links or privately distribute PNG keys.
